# 决策：正常退出只保留锁定的标签

状态：当前有效。范围：会话在正常退出时写什么。

## 问题与约束

若每次退出都恢复当时所有标签，临时开的标签会一直堆着。若正常退出什么都不留，用户又会丢失特意留下的工作区。崩溃和 `kill` 则不该惩罚用户：那一次布局应当还能回来。

## 决定与理由

标签默认不锁定。正常退出（`save_now(final=True)`）调用 `retain_locked_tabs`，只把锁定的标签写入会话。没有标签列表的窗口，例如单个终端或没有标签条的分屏，整窗保留。若因此一个终端都不剩，下次普通启动开一个新窗口，不回退到配置里的 `default` 布局。

运行中的防抖保存仍写完整布局。进程被杀死时来不及做这次裁剪，磁盘上的文件还是完整布局，下次会恢复。崩溃标记存在时改读轮转后的 `.prev` 或 `.prev2`。

曾考虑正常退出也恢复全部标签，用「下次启动不恢复」当作唯一的干净启动。那样临时标签无法逐个丢掉，所以不采用。

## 影响与退出条件

用户若发现「昨天的标签没了」，先看该标签有没有锁。这不是保存失败。若产品改成默认锁定，要同时改需求 TX-01.4 和本记录，并说明旧会话文件里缺少 `locked` 列表时如何处理。现在的规则是：缺省视为未锁定。

## 现行约束与入口

需求见 [TX-01.4](../requirements/terminatorx.md)、[TX-01.5](../requirements/terminatorx.md)。实现是 `terminatorlib/session.py` 的 `retain_locked_tabs`。现象说明见 [故障维护](../guides/maintenance.md)。
